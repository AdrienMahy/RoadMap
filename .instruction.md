# Data & IT Roadmap — Copilot Instructions

## 1. Project Overview

This project is an internal web application used to manage and present the Data & IT development roadmap.

The application has two distinct areas:

- **BOARD**: read-only interface designed for the Board/management.
- **DEV**: administration interface used by the Chief of Data & IT to create and manage projects, stages and development points.

The application must remain intentionally simple. It is NOT intended to become a full project-management tool such as Jira, Linear or Monday.

The primary objective is to provide a clear, elegant and always up-to-date view of the Data & IT roadmap.

---

# 2. Core Principles

## Simplicity first

Do not add unnecessary features.

Every feature must answer one of these questions:

1. Does it help the Board understand the roadmap?
2. Does it help the developer maintain the roadmap quickly?
3. Does it improve clarity or usability?

If the answer is no, do not implement it unless explicitly requested.

## Internal-first architecture

This is an internal application.

It is intended to be:

- hosted internally;
- accessible through the club's internal network;
- connected to an internal database;
- simple to deploy and maintain.

Avoid unnecessary external services.

## Design quality

The application must have a modern, premium and professional interface.

The target is closer to:

- Linear
- Vercel
- Notion

than to a traditional enterprise dashboard.

Avoid:

- excessive cards;
- unnecessary charts;
- excessive colors;
- visual clutter;
- complex navigation;
- excessive animations.

The interface should feel clean, modern and fast.

---

# 3. Application Structure

The application contains two main sections.

## BOARD

The Board interface is read-only.

Purpose:

> Give the Board an immediate understanding of the current state of Data & IT projects and their upcoming milestones.

The Board should be able to understand the state of the roadmap within approximately 10 seconds.

The Board must NOT be able to modify projects, stages or points.

Main information:

- projects;
- current status;
- stages;
- development points;
- timeline;
- upcoming milestones;
- latest updates;
- last update date.

---

## DEV

The DEV interface is the administration area.

Purpose:

> Allow the Chief of Data & IT to quickly create, modify and organize the roadmap.

The developer must be able to:

- create projects;
- edit projects;
- archive projects;
- create stages;
- edit stages;
- delete/archive stages;
- create development points;
- edit development points;
- change statuses;
- define dates;
- reorder stages;
- reorder points;
- add updates.

The DEV interface should prioritize speed and ease of use.
